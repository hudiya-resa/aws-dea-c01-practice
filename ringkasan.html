Domain 1: Data Ingestion and Transformation

Cara memasukkan data ke AWS, mengubahnya jadi berguna, mengatur alur pipeline, dan konsep pemrograman di baliknya.

Domain 1 introduction

Ingestion dan integration

  • Data ingestion: memindahkan data dari titik A ke titik B.
  • Data integration: menggabungkan beberapa sumber jadi dataset baru (contoh: advertising plus web analytics jadi user profile). Ini bagian dari transformation.
  • Cara ingest: direct database connection, change data capture, API, message queue, event streaming, file export, object storage (Amazon S3).
  • Cara transform: queries, modeling, transformations.

Empat task statement

  • 1.1 Perform data ingestion: throughput, latency, streaming dan batch.
  • 1.2 Transform and process data: ETL pipeline, volume, velocity, variety, distributed computing.
  • 1.3 Orchestrate data pipelines: jadwal, dependency, event-driven, serverless workflow.
  • 1.4 Apply programming concepts: CI/CD, SQL, infrastructure as code, data structure (graph, tree).

Lesson 1: Perform data ingestion

Lifecycle dan konsep dasar

  • Stage: generation, storage, ingestion, transformation, serving.
  • Generation adalah source system. Data engineer memakai datanya tapi tidak mengendalikan sistemnya.
  • Dua konsep besar: batch vs streaming, push vs pull.
  • Alur: producer (database, mobile, aplikasi) ke alat ingestion ke consumer (EC2, database AWS, Lambda).

Replayability

  • Pipeline bisa memproses ulang data saat gagal atau logika berubah.
  • Rancang event-driven: Amazon S3, Amazon Kinesis, Amazon EventBridge memicu event saat data baru datang.
  • Uji idempotent: data sama diproses berkali kali tanpa hilang atau dobel.
  • Pasang checkpoint supaya bisa lanjut dari titik terakhir yang sukses.
  • Simpan raw atau intermediate data di S3 (versioning, compliance, replay). Deploy dengan CloudFormation atau AWS CDK.

Contoh S3, Athena, Redshift

  • File TSV di S3: daftarkan ke Amazon Athena lalu query ad hoc dengan SQL. Ubah ke Parquet supaya query lebih cepat.
  • Tim BI butuh warehouse: masukkan ke Amazon Redshift, gabungkan dengan data S3 lewat Redshift Spectrum.
  • Tabel Athena ikut update saat data baru tiba: AWS Glue crawler.
  • COPY lambat dari satu gzip besar: pecah jadi file kecil, jumlahnya kelipatan jumlah slice. COPY memakai MPP dan memuat paralel. Atur distribution key.

Service per use case

  • Data lake: S3, tanpa schema di awal. Warehouse atau lakehouse: Redshift dan Redshift Spectrum.
  • Big data processing: Amazon EMR. Real-time analytics: Kinesis dan Amazon MSK.
  • Operational analytics (monitoring aplikasi, log, clickstream) near real time: Amazon OpenSearch Service.
  • Transactional (data kecil, cepat): DynamoDB dan RDS. AWS DMS memakai transaction log untuk CDC, migrasi engine (Oracle ke Aurora), dan replikasi terus ke S3.

Lima V data

  • Variety: jenis data. Volume: ukuran dan pertumbuhan, perhatikan batas ukuran record per service.
  • Velocity: bedakan real time dan near real time. Service untuk traffic naik turun: Kinesis, MSK, OpenSearch, Lambda.
  • Veracity: kualitas dan kelengkapan (contoh sensor IoT mati).
  • Value: V paling penting. Data yang diolah tapi tidak bernilai adalah buang uang.

Keluarga Kinesis

  • Streaming: banyak event kecil (sekitar 1 KB), hot data, dibatasi waktu atau jumlah event.
  • Kinesis Data Firehose: buffer sesuai periode lalu tulis ke S3, Redshift, OpenSearch Service. Catatan: sekarang bernama Amazon Data Firehose.
  • Kinesis Data Streams: real time, latency rendah, aplikasi custom.
  • Amazon Managed Service for Apache Flink (dulu Kinesis Data Analytics): analitik stream pakai SQL atau Flink.
  • Kinesis Video Streams: video, audio, thermal imagery, radar. Kinesis Agent: baca file lalu kirim ke Streams atau Firehose.
  • Hot shard (write throttled): UpdateShardCount untuk tambah shard, random partition key, pasang alarm metrik.

Service ingestion lain dan batch

  • MSK untuk mengganti cluster Kafka yang ada, bayar cluster walau idle. Kinesis serverless, bayar throughput.
  • Amazon AppFlow: dari SaaS. AWS Transfer Family: FTP dan SFTP ke S3. AWS DataSync: on-premises NFS dan SMB. Snow Family: data sangat besar.
  • Batch: payload besar, jadwal per jam sampai mingguan, untuk cold data. EMR (Spark plus JDBC) atau AWS Glue (fully managed ETL, JDBC, Glue Studio).
  • Stateful: ElastiCache for Redis, RDS. Stateless: Lambda, API Gateway, S3.

Lesson 2: Transform and process data

Modeling, OLTP, OLAP

  • Pahami model conceptual, logical, physical, normalization, dan data vault.
  • OLTP: transaksi real time, state terbaru, storage kecil, respons cepat (order, payment).
  • OLAP: analisis dan reporting, histori, star atau snowflake schema, storage terabyte sampai petabyte.
  • Transformasi: ubah tipe data, standarkan format, buang data jelek, agregasi untuk report atau fitur ML.
  • Transformasi bisa terjadi saat ingestion. Contoh: Firehose menulis Parquet.

Service processing

  • Cloud computing: Lambda, EMR, Glue, Redshift. Distributed: EMR, AWS Batch, Step Functions.
  • Lambda untuk validasi dan transform ringan, misalnya tiap file CSV yang masuk S3.
  • AWS Glue: serverless, engine Python atau Spark, data di S3.
  • Glue Data Catalog memberi logical view atas file hasil DMS (satu prefix per tabel). Query lewat Athena atau dipakai di kode ETL EMR dan Glue.
  • Glue crawler menebak schema dan mengisi katalog otomatis.

Glue vs EMR vs Flink

  • EMR: Hadoop penuh (Spark, Hive, Hudi, HBase, Presto, Pig), lebih mampu dari Glue, tapi tidak fully managed.
  • Spark di EMR: buat cluster, atur memory dan executor cores, kirim job dengan spark-submit, scale naik atau turun.
  • Glue: fully managed, cukup untuk cleansing, enrichment, data movement.
  • Flink: transformasi dasar SQL. Transformasi kompleks pindah ke EMR atau Glue.

Contoh arsitektur

  • IoT aman near real time: Firehose ke S3, Lambda membuang data sensitif sebelum disimpan.
  • Log web di EC2: Kinesis Agent ke Firehose, ke S3 dan ke Flink, lalu Firehose kedua ke OpenSearch, visual di Kibana.
  • Kurangi beban Redshift saat join histori di S3: Redshift Spectrum external table.
  • Enrich CloudWatch Logs dengan DynamoDB: subscription CloudWatch Logs ke Firehose, Lambda untuk enrich, tujuan S3.

Troubleshooting

  • Cek log service, kualitas data tiap stage, lalu logika mapping, filter, agregasi.
  • Glue punya development mode dan debugging mode. Debug dengan dataset kecil.
  • Optimasi: partitioning, paralel, tuning memory dan executor, caching.
  • Incremental processing untuk data baru saja. Retry untuk gangguan sementara.
  • Uji unit, integration, end-to-end di staging.

Konektivitas dan data API

  • JDBC: Java API. Siapkan driver, buka port di security group inbound, URL berisi host, port, nama database.
  • ODBC: instal driver, buat DSN, aplikasi konek lewat DSN.
  • RDS, Aurora, Redshift mengurangi konfigurasi JDBC atau ODBC manual.
  • Data API: API Gateway (auth, rate limiting, caching, versioning) plus Lambda. Keamanan: IAM, Certificate Manager, API key, OAuth.
  • Cache: ElastiCache atau cache API Gateway. Monitor: CloudWatch. CI/CD: CodePipeline dan CodeBuild.

Lesson 3: Orchestrate data pipelines

Konsep pipeline

  • Kenali arsitektur: data warehouse, data lake, lakehouse, Lambda, Kappa, data mesh. Rujukan: Well-Architected Framework, enam pilar.
  • Pipeline: kumpulan task dengan urutan tertentu, sekuensial atau paralel. Urutannya disebut workflow.
  • Serverless orchestration: Step Functions dan Lambda.
  • Airflow wajib DAG, Step Functions tidak.
  • Correction Notice: video menyebut "Directed Acrylic Graph". Yang benar Directed Acyclic Graph, graph berarah tanpa siklus.
  • Banyak file kecil jadi satu batch: kirim manifest file, S3 event notification hanya untuk prefix "manifest", lalu cek tiap file. Tetap event-driven.

Kegagalan dan retry

  • Data quality (dapat JSON padahal menunggu CSV) dan code error: hard failure.
  • Endpoint error: jaringan sementara soft failure, permission salah hard failure.
  • Dependency error: di dalam atau antar pipeline.
  • Step Functions: interval 10 detik, backoff rate 1.5, jeda 10, 15, 22.5 detik.
  • Alert: Amazon SNS topic dengan subscription email.

Pilihan service

  • Serverless: AWS Data Pipeline dan Step Functions. Managed open source: Amazon MWAA. Khusus: Glue workflows.
  • Data Pipeline: ETL terjadwal antara AWS dan on-premises, bisa JDBC on-premises. Instruktur memilihnya untuk lingkungan kurang kompleks.
  • Step Functions: visual low code atau Amazon States Language (JSON), untuk yang lebih kompleks. Dipicu EventBridge atau API.
  • Glue workflows: kalau pipeline murni komponen Glue, pakai trigger. Service lain lewat Glue Python shell job dengan Boto3.
  • MWAA: Airflow terkelola, DAG ditulis Python.
  • Catatan: AWS Data Pipeline sudah maintenance mode sejak 2024. CloudWatch Events sekarang bagian dari EventBridge.

Contoh pipeline

  • Raw zone dari Firehose, DMS, DataSync. S3 memicu Lambda yang menjalankan crawler.
  • Rule CloudWatch Events memicu Glue ETL ke Parquet di processed zone, lalu SNS kirim email.
  • Step Functions dengan EMR: Lambda submit Spark job, tunggu, cek status, ke success atau failure.
  • Choice state membaca job status. Catch statement menjalankan Lambda notifikasi saat error.
  • Athena atas data di dua Region: Glue crawler di satu Region mengkatalog semua Region.

Best practice

  • Distributed processing, auto scaling, partitioning.
  • Storage fault-tolerant: S3 atau EFS. Backup: S3 atau AWS Backup.
  • CloudWatch alarm. Retry dengan Step Functions atau Glue workflows.
  • Validasi data, testing, version control, CI/CD.

Lesson 4: Apply programming concepts

SQL vs Spark

  • SQL: standar dan dikenal luas. Spark: lebih fleksibel untuk proses kompleks dengan syarat latency dan throughput.
  • Spark di AWS: Glue (serverless), EMR, ECS atau EKS, partner seperti Databricks.
  • Target di Redshift berarti ELT, pakai SQL.
  • Transform di Spark lalu load ke warehouse berarti ETL, beban warehouse fokus ke query user.
  • Redshift: parser dan optimizer membuat query plan, execution engine mengirim kode ke compute node.

Alat ETL

  • EMR: Hadoop, Spark, HBase, Presto, YARN, Tez, Pig, satu sampai ribuan node.
  • Data Pipeline: data node dan activity (S3 data node, Hive activity di EMR, Redshift copy activity).
  • Glue Studio: transformasi visual SQL di engine Spark untuk yang tidak bisa Spark. Glue DataBrew: transformasi atas sekumpulan file.
  • Nama kolom Athena hanya alfanumerik dan underscore (/var/log jadi var_log).

Optimasi runtime

  • Paralel dan batch processing.
  • Parquet atau ORC, kompresi, partisi per tanggal atau Region.
  • Filter data sejak awal, incremental processing.
  • Tuning memory dan parallelism, monitor dengan CloudWatch.

IaC, CI/CD, Lambda

  • CloudFormation atau CDK untuk deploy berulang. AWS SAM untuk Lambda, Step Functions, DynamoDB.
  • Template di CodeCommit atau GitHub, CI/CD jalan saat ada commit. Catatan: CodeCommit tidak menerima pelanggan baru sejak 2024.
  • Lambda: atur memory, concurrency limit, timeout, retry. Asynchronous invocation kalau tidak perlu respons langsung.
  • Provisioned concurrency untuk prewarm. Lambda di VPC menambah latency.

Data structure dan algoritma

  • Data structure: relational, NoSQL, warehouse, distributed file system, message queue, tree, hash table.
  • Algoritma untuk satu data structure jadi tidak efisien di data structure lain. Sorting besar: Quicksort atau Merge Sort.
  • Contoh: data pelanggan besar di HDFS di EMR, diproses dengan MapReduce.
  • Data hilang di consumer Kinesis Java: idempotent processing dan shard iterator ke posisi sebelum error.

Jebakan ujian

  • Data Streams (real time, aplikasi custom) vs Firehose (buffer, near real time, langsung ke tujuan).
  • Real time vs near real time, baca kata kuncinya.
  • Kinesis vs MSK: solusi baru pilih Kinesis, mengganti Kafka yang ada pilih MSK.
  • Glue (fully managed) vs EMR (lebih lengkap, perlu kelola cluster).

  • Glue workflows hanya pas kalau pipeline murni Glue.
  • Stateful (ElastiCache, RDS) vs stateless (Lambda, API Gateway, S3).

Domain 2: Data Store Management

Lesson 1: Choose a data store

Tiga jenis storage dasar

  • Amazon S3: object storage, highly available, scalable, durable. Untuk static content, backup, media, dan storage dasar data lake.
  • Amazon EFS: file storage fully managed yang dipakai bersama banyak EC2 instance.
  • File storage lain: FSx for Windows File Server, FSx for Lustre, FSx for NetApp ONTAP.
  • Amazon EBS: block storage persisten yang di-attach ke EC2. Untuk database dan aplikasi transaksional yang butuh low latency.

Database dan warehouse

  • Amazon RDS: managed relational database (MySQL, PostgreSQL, Oracle, SQL Server, dan lain-lain).
  • DynamoDB: managed NoSQL, latency single-digit millisecond di skala berapa pun. Untuk real-time, gaming, IoT, dynamic scaling.
  • Catatan: kursus menyebut DynamoDB mendukung graph, memory, dan search. Dalam praktik DynamoDB adalah key-value dan document database.
  • Amazon Redshift: data warehouse skala petabyte untuk analytics dan BI, juga bisa menangani semi-structured dan unstructured data volume besar.
  • AWS Lake Formation: build, secure, dan manage data lake. Bisa crawl, catalog, dan siapkan data.

Faktor dan contoh pilihan

  • Faktor performa: IOPS, scalability, durability, data access pattern.
  • Highly parallel file system untuk HPC, analytics, ML skala besar: FSx for Lustre.
  • In-memory caching, session storage, real-time analytics: ElastiCache.
  • Redshift cocok untuk 30 TB data, banyak aggregated query dan complex join yang hanya memakai sebagian kolom. Alasannya columnar storage (I/O kecil), compression, parallel processing, dan dukungan SQL JOIN.

Migrasi dan akses data

  • COPY command memuat data file ke tabel Redshift, misalnya dari S3 atau EMR. COPY mengubah string ke data type kolom target.
  • Kalau butuh konversi lain atau konversi default error, atur lewat parameter COPY.
  • Data RDS: 3 bulan terbaru dipakai analitik, data lama sesekali di-join. Solusi: data lama ke S3, job harian dari RDS ke Redshift, join keduanya lewat Redshift Spectrum.
  • Petabyte data key-value, akses langsung, SQL-like interface: Hive di EMR, simpan ke DynamoDB.
  • EMR untuk job pendek: nyalakan dan matikan cluster, bayar per detik. Workload panjang: cluster highly available dengan auto scaling.

Mencegah akses tidak sah (Redshift dan RDS)

  • IAM untuk akses ke cluster dan resource, policy sesuai role.
  • Security group, encryption, dan key di AWS KMS.
  • Parameter group untuk parameter database, termasuk locking untuk concurrency.
  • Database auditing, plus jadwal rutin cek access log dan audit trail.

Lesson 2: Understand data cataloging systems

Apa itu data catalog

  • Metadata repository: lokasi, deskripsi atau schema, dan runtime metrics data.
  • Dipakai untuk federated query dan ETL saat data tersebar di banyak lokasi.
  • AWS Glue Data Catalog berisi referensi source dan target ETL job. Satu metadata table mewakili satu data store.
  • Biasanya diisi crawler, tapi ada cara lain menambah metadata table.
  • Athena memakai catalog untuk tahu lokasi S3, format file (Parquet, CSV), dan partition.

Lake Formation dan lintas akun

  • Glue menyimpan business attribute sebagai key-value tag di level tabel. Lake Formation bisa key-value property di level kolom.
  • Lake Formation mengatur permission di level database, table, dan column.
  • Kasus 4 AWS account, tiap business unit hanya akses datanya: data lake storage di tiap akun, catalog ke akun pusat dengan Lake Formation.
  • Lalu update S3 bucket policy dengan Lake Formation service-linked role, dan pakai Lake Formation permission untuk akses spesifik.
  • User dan Glue ETL job bisa join tabel lintas akun dengan proteksi table-level dan column-level.

Menjaga catalog tetap terbarui

  • Jalankan Glue crawler setelah data baru masuk.
  • Job baru di production: cek bahwa job memakai AWS Glue API untuk update catalog.
  • Sinkronisasi partition penting untuk data terpartisi di S3 (tanggal, Region, kategori).
  • Langkah: buat database Glue, buat crawler, tentukan partitioning schema, jalankan, jadwalkan sesuai frekuensi ingest, query dengan Athena.
  • Partition yang tidak terdeteksi otomatis ditambah atau diubah lewat Glue API.

Glue connection

  • Connection untuk data source (ingest) atau data target (write).
  • S3: path bucket dan pola inclusion/exclusion. RDS: endpoint, port, credential.
  • Bisa test connection dulu. Connection dipakai crawler dan ETL job.

Komponen metadata dan catalog

  • Metadata: schema, data type, data source, timestamp, data quality metrics (akurasi, kelengkapan, konsistensi), ownership dan access control.
  • Catalog: table dan database, table schema, partition info, lokasi (S3 path, endpoint), statistik dari crawling.
  • Catalog juga: data lineage dan dependency, tag dan label, access control policy, integrasi dengan tools analytics.

Klasifikasi data

  • Klasifikasi: kelompokkan data menurut sensitivitas supaya kontrol keamanannya pas.
  • IAM untuk akses. KMS untuk encryption key. VPC dan security group untuk isolasi.
  • SCP di AWS Organizations mencegah member account memakai aksi atau service tertentu.
  • Amazon Macie memakai ML untuk menemukan, mengklasifikasi, dan melindungi sensitive data.

Lesson 3: Manage the lifecycle of data

Hot, warm, cold

  • Tanya: seberapa penting data, berapa lama disimpan, seberapa sering diakses.
  • Data baru biasanya lebih sering diakses.
  • Semua di hot storage: cepat tapi mahal. Semua di cold: retrieval lama dan bisa ada biaya retrieval.
  • Transformasi menghasilkan dataset baru yang juga harus dikelola.

Optimasi biaya dan retention

  • S3 Lifecycle policy memindahkan data ke storage class lain, atau menghapusnya untuk kebutuhan bisnis dan hukum.
  • Redshift: elastic resize untuk tambah atau kurangi node dan ganti node type.
  • Ketahui nilai data, cara simpan, dan siapa yang akses. Tanyakan juga apakah data bisa dibuat ulang.
  • Regulasi bisa mewajibkan retention tertentu, jadi perlu retention policy dan archiving yang tetap bisa dicari.

Resiliency dan availability

  • S3 otomatis mereplikasi data ke beberapa Availability Zone.
  • RDS Multi-AZ memberi automatic failover saat satu AZ gagal.
  • Backup: AWS Backup, automatic snapshot, atau replikasi ke Region lain.
  • S3 Versioning melindungi object dari terhapus atau ter-overwrite.

Menghapus data lama

  • DynamoDB Time to Live (TTL) menghapus item otomatis setelah timestamp tertentu.
  • Kasus MSK ke Redshift, query makin lambat dan maintenance makin lama: buat time series table identik per rentang waktu.
  • Hapus data lama dengan DROP TABLE, bukan DELETE besar, supaya tidak perlu VACUUM.
  • Tabel kecil per waktu lebih teroptimasi untuk query. Kalau di-sort per timestamp, VACUUM bisa tidak perlu.

Kasus S3 dan Athena

  • CSV di S3 Standard di-query Athena: ubah dengan Glue ETL ke format columnar, compress, partition.
  • Lifecycle: S3 Standard ke S3 Standard-IA setelah 6 bulan, lalu ke S3 Glacier setelah 2 tahun.

Lesson 4: Design data models and schema evolution

Data modeling

  • Strict normalization kurang cocok untuk event data yang beragam.
  • Redshift mendukung star schema, snowflake schema, dan Kimball.
  • Inmon dan data vault bisa, tapi butuh transformasi tambahan dan solusi custom.
  • Redshift Serverless dengan Query Editor v2: buat schema dan tabel, import data visual.

Spark dan lineage

  • EMR menjalankan Spark cluster on demand. spark.read untuk structured data dari S3, spark.sparkContext.textFile untuk raw text.
  • Glue crawler menebak schema di S3 dan membuat tabel di catalog, lalu dipakai Spark.
  • Athena untuk interactive SQL di S3. Comprehend untuk NLP teks unstructured.
  • Data lineage melacak asal, transformasi, dan alur data. Membantu error tracking dan debugging.
  • SageMaker ML Lineage Tracking mencatat input data, model, hyperparameter, transformasi, model artifact, dan inference data. Bisa diintegrasikan dengan Glue dan S3.

Optimasi data

  • RDS: index di kolom yang sering dipakai WHERE atau JOIN. DynamoDB: pilih primary key dan secondary index sesuai pola query.
  • S3: partisi ke folder logis, query subset dengan Athena atau Glue.
  • Redshift: distribution key dan sort key untuk sebar data merata dan kurangi data movement.
  • Compression: gzip atau bzip2 di S3, compression encoding kolom di Redshift. Format Parquet atau ORC di S3.
  • Cache: ElastiCache atau CloudFront. Data historis: S3 Glacier atau Glacier Deep Archive.
  • DynamoDB provisioned throughput plus auto scaling. Tuning query: RDS Performance Insights, Redshift query monitoring. Transfer: DataSync atau Transfer Family.

Jenis data dan service

  • Structured: RDS, Aurora, Redshift.
  • Semi-structured: DynamoDB, DocumentDB (MongoDB compatibility), Athena, S3.
  • Unstructured: S3, Rekognition, Transcribe, Comprehend.

Schema evolution

  • Field bertambah atau hilang, tipe berubah (string ke integer). Tujuannya menjaga data lama dan backward compatibility.
  • DynamoDB: cukup update aplikasi, data lama tanpa atribut baru tetap bisa dipakai.
  • RDS dan Aurora lebih rumit: pakai AWS DMS dengan downtime minimal, atau stored procedure.
  • Data lake S3 memakai schema on read: data mentah, schema diterapkan saat query lewat Athena atau Glue.
  • AWS Glue mendukung schema versioning. Avro, Parquet, ORC mendukung schema evolution by design.
  • Catatan: kursus menyebut Avro columnar. Avro sebenarnya row-based, yang columnar Parquet dan ORC.

Antisipasi dan konversi schema

  • Proaktif: dead letter queue, schema registry, validasi schema, versioning, backup sebelum ubah, monitoring dan alerting.
  • Test schema baru: Glue, AWS Data Pipeline, atau custom script. Glue DataBrew untuk profiling data.
  • Catatan: AWS Data Pipeline sudah maintenance mode dan tertutup untuk pelanggan baru.
  • AWS SCT mengonversi schema dan code antar engine (data type mapping, stored procedure, index), dengan assessment masalah.
  • AWS DMS bekerja bersama SCT saat migrasi ke RDS, Aurora, Redshift, dan lainnya.

Lesson 1: Automate data processing by using AWS services

Infrastructure as code dan CI/CD

  • CloudFormation template bisa membuat seluruh pipeline: S3 bucket, EventBridge rule, Lambda, SNS topic, Step Functions, Glue job, Glue crawler.
  • Contoh alur: file masuk S3, EventBridge memicu Lambda validasi, Lambda memulai state machine, state machine menjalankan Glue job, lalu Glue crawler memperbarui Data Catalog. SNS memberi notifikasi kalau gagal.
  • Template disimpan di S3 atau CodeCommit untuk akses dan versi.
  • CodePipeline mengotomatiskan CI/CD. Commit file Python ke CodeCommit memicu CodeBuild untuk build, integrasi, dan unit test.
  • Continuous delivery menambah end-to-end test: ingest file, jalankan transformasi, validasi output.
  • Catatan: CodeCommit sudah ditutup untuk pelanggan baru sejak Juli 2024, tapi masih bisa muncul di soal.

Orchestration: Amazon MWAA vs Step Functions

  • Amazon MWAA adalah Apache Airflow managed. Workflow ditulis sebagai DAG berisi task dengan dependency (Spark job, Glue job, AWS Batch job).
  • Step Functions adalah layanan serverless berbentuk state machine. Tiap state bisa menjalankan task, membuat keputusan, atau menunggu event.
  • Step Functions punya error handling, retry, dan visualisasi workflow bawaan.
  • MWAA cocok untuk workflow kompleks yang fleksibel dan berbasis kode. Step Functions cocok untuk workflow serverless dan event-driven dengan layanan AWS.

Troubleshooting MWAA

  • Cek CloudWatch Logs untuk error dan exception, lalu log Apache Airflow sendiri.
  • Periksa IAM role dan permission untuk MWAA, DAG, dan layanan terkait (Glue, S3, EMR).
  • Pastikan dependency dan file reference DAG benar, dan layanan eksternal bisa diakses dari environment MWAA.
  • Sesuaikan jumlah dan ukuran worker node supaya tidak out-of-memory.
  • Uji DAG di lokal atau test environment dulu, pakai versi Airflow dan plugin terbaru.

Consume dan maintain data API

  • Lambda memanggil API dan memproses respons, dipicu event atau API Gateway.
  • API Gateway memberi endpoint managed untuk klien eksternal dan bisa jadi frontend untuk Lambda.
  • AWS SDK menangani authentication, signing request, dan parsing respons.
  • Pantau error rate dan latency dengan CloudWatch.
  • Caching dengan API Gateway caching atau ElastiCache. Throttling dan rate limiting di API Gateway mencegah penyalahgunaan.
  • Amankan dengan IAM dan OAuth. API versioning menjaga backward compatibility. Lambda layers mengatur dependency dan mengecilkan package.

Query dan events

  • Athena cocok untuk eksplorasi cepat tanpa setup infrastruktur dan bayar per query. Hasil bisa diunduh atau disimpan ke S3.
  • EventBridge rule mencocokkan event berdasarkan pattern (atribut, custom event bus), lalu mengirim ke satu atau lebih target.
  • API call ke EventBridge dicatat CloudTrail. EventBridge schema registry adalah fitur opsional untuk mengelola event schema.
  • Contoh Step Functions: Lambda cek ekstensi file, Choice state memutuskan. File didukung diproses Lambda kedua, file tidak didukung memicu notifikasi SNS.
  • CloudTrail tidak mencatat object-level data events S3 secara default. Buat trail yang mencatat management dan data events.
  • EventBridge rule dengan service S3, operasi dan bucket tertentu, dan target state machine memulai workflow saat file masuk.

Lesson 2: Analyze data by using AWS services

Operasi manipulasi data

  • Aggregation merangkum banyak record jadi satu nilai: Redshift (sum, average, count), Athena (GROUP BY), OpenSearch Service (date histogram, term aggregation).
  • Rolling average menghitung rata-rata dalam window untuk meratakan fluktuasi: Redshift (window function AVG) dan QuickSight (moving calculation).
  • Grouping: Redshift dan Athena (GROUP BY), QuickSight (dimensions dan aggregations).
  • Pivoting mengubah baris jadi kolom: Redshift (PIVOT clause) dan QuickSight (pivot table).

Layanan untuk data consumer

  • QuickSight: dashboard interaktif dan ad hoc analysis.
  • AWS Glue DataBrew: visual data preparation tanpa kode.
  • Athena: SQL di data S3. Redshift: SQL untuk dataset besar. EMR: Spark dan Hadoop.
  • AWS Glue: discover, catalog, transform, dan generate kode ETL otomatis.
  • AWS Data Pipeline: orkestrasi data antar layanan AWS dan on-premises. Catatan: Data Pipeline sudah maintenance mode, tidak menerima pelanggan baru.
  • Lake Formation: akses aman ke data dari banyak sumber di data lake.

Contoh skenario

  • Script di EC2 tiap 8 jam membersihkan data S3 jadi CSV untuk spreadsheet, lalu butuh dashboard dan search. Solusi: pindah ke Lambda, kirim hasil ke OpenSearch, picu dengan EventBridge tiap 8 jam.
  • Data sensor IoT dengan laporan visual harian yang cost-effective: EMR transient cluster agregasi tiap malam lalu otomatis terminate, laporan di QuickSight.
  • EMR punya dua jenis cluster: transient dan persistent.

SQL di berbagai layanan

  • Sintaks SQL konsisten walau tiap layanan menjalankannya berbeda. RDS dan Aurora memakai SQL untuk CRUD.
  • DynamoDB mendukung PartiQL, bahasa query kompatibel SQL untuk data terstruktur, semi-structured, nested, dan schemaless.
  • Amazon DocumentDB kompatibel MongoDB dan bisa memakai query mirip SQL.
  • Athena bisa menjalankan aplikasi Spark lewat Python atau Athena notebook APIs. EMR menyediakan Jupyter Notebook untuk kode Spark.

Verifikasi dan cleaning data

  • Lambda untuk validasi dan enrichment custom. Athena untuk verifikasi berbasis SQL.
  • QuickSight untuk eksplorasi visual. Jupyter Notebooks untuk cleaning kompleks.
  • SageMaker Data Wrangler untuk menyiapkan data bagi model ML.
  • Satu workflow wajar memakai beberapa layanan sekaligus.

Lesson 3: Maintain and monitor data pipelines

Monitoring dan observability

  • Sisi data: cek input, output, dan schema. Jalankan quality test di input dan hasil transformasi supaya bisa flag issue, rollback, dan cari root cause.
  • Metric operasi: query queue length, query concurrency, memory usage, storage utilization, network latency, disk I/O.
  • Query lambat direfactor. Kalau query sudah bagus, tune database (cluster atau cache tabel) atau scale up compute.
  • Tool: CloudWatch, X-Ray, CloudWatch Logs Insights, GuardDuty, Inspector, Security Hub. Aplikasi harus di-instrument untuk traces, metrics, dan logs.

Logging data aplikasi

  • CloudWatch Logs menyimpan log dan memberi notifikasi saat threshold tercapai.
  • CloudWatch Events mengirim system events near real-time dengan rule. Catatan: CloudWatch Events sekarang bagian dari EventBridge.
  • EventBridge merutekan event dari aplikasi sendiri, SaaS, dan layanan AWS ke target seperti Lambda.
  • X-Ray memberi end-to-end tracing untuk aplikasi terdistribusi dan microservices.
  • Lambda otomatis mencatat tiap invocation. ALB access logs mencatat request time, client IP, user agent.
  • RDS punya error log, slow query log, dan general log.
  • Log group adalah wadah log streams. Bisa dibuat lewat CloudFormation. Default retensi CloudWatch Logs selamanya, atur retention policy untuk biaya dan aturan retensi.

Traceability dan audit

  • CloudTrail mencatat semua API call: siapa, apa, kapan. Log dikirim ke S3 atau CloudWatch Logs.
  • AWS Config mencatat riwayat konfigurasi resource. AWS Managed Rules menilai kepatuhan terhadap best practice.
  • CloudFormation StackSets men-deploy konfigurasi CloudTrail, CloudWatch, dan Config ke banyak akun dan Region.
  • VPC Flow Logs mencatat IP traffic network interface di VPC.
  • Security Hub menggabungkan finding GuardDuty, Inspector, dan Config ke satu dashboard.
  • Macie mengirim policy finding dan sensitive data finding ke EventBridge sebagai event, dan ke Security Hub kalau publication settings diatur. Macie tidak mengirim log ke CloudWatch Logs.

Troubleshooting performa

  • Bandingkan CPU, memory, network, disk I/O, dan performa database dengan baseline.
  • Cek AWS Health Dashboard dulu sebelum debug aplikasi.
  • Baca log aplikasi di CloudWatch Logs, lalu log spesifik Lambda, RDS, atau EC2.
  • VPC Flow Logs dan Network Load Balancer access logs membantu melihat latency dan packet loss.
  • Kasus Kinesis Data Streams 40 shard, consumer KCL di Auto Scaling group, hasil ke DynamoDB: CPU di bawah 35 persen dan tidak ada ProvisionedThroughputExceededException. Jadi naikkan write capacity DynamoDB.
  • Redshift dengan long running query: atur scaling pada workload management (WLM) queue lewat parameter group, supaya query pendek tidak antre.

Error handling per layanan

  • Managed service menangani banyak error sendiri. Di EMR dan Kinesis Data Streams, kamu yang memprogram perilaku saat error.
  • Aplikasi Hadoop baru di EMR: aktifkan debugging, uji dengan subset data kecil yang representatif, jalankan step satu per satu.
  • Kinesis Data Streams: masalah producer (gagal connect, lambat menulis) dan consumer (masalah record, menerima lambat).
  • Managed Service for Apache Flink: masalah umum adalah akses stream, data hilang, gagal proses, error aplikasi. Selidiki lewat CloudWatch Logs.
  • Flink bisa mendeteksi anomali dengan random cut forest, lalu Lambda bertindak. Catatan: RANDOM_CUT_FOREST berasal dari Kinesis Data Analytics for SQL, yang sudah dihentikan AWS.
  • Firehose retry sampai retry duration habis, lalu backup ke S3 backup bucket. Kalau tujuan S3 atau backup S3 gagal, retry sampai retention period habis. Catatan: namanya sekarang Amazon Data Firehose.

Lesson 4: Ensure data quality

Prinsip

  • Konsumen harus percaya pada data. Kerja mundur dari pelanggan: siapa pemakai, bagaimana dipakai, apa yang dibutuhkan.
  • Tidak menerbitkan data lebih baik daripada menerbitkan data buruk. Check otomatis harus bisa menghentikan pipeline.
  • Duplikat di kolom primary key: kirim notifikasi. Proses tidak selalu harus dihentikan seluruhnya.
  • Taruh check sebelum, selama, dan sesudah transformasi. Terlalu banyak check memicu false positive, terlalu sedikit membuat masalah lolos.

Data profiling dan validation

  • Profiling melihat null, distribusi, anomali, cardinality, relasi antar field, dan statistik (min, max, mean, median, standard deviation).
  • DataBrew membuat profil tanpa kode. Athena dan Redshift untuk profiling dengan SQL. EMR Spark untuk script custom. Ada juga tool di AWS Marketplace.
  • Validation punya empat dimensi: completeness, consistency, accuracy, integrity.
  • Check saat pemrosesan: DataBrew recipes untuk field kosong, format, dan uniqueness. EMR Spark untuk check custom.
  • Lambda untuk check kompleks dan remediasi, Step Functions untuk orkestrasi berdasarkan hasil validasi. Data Wrangler untuk missing value dan duplikat.

Duplikat di Redshift

  • Kasus: CSV di S3, Glue crawler mengisi Data Catalog, Glue job menulis ke Redshift, lalu muncul duplikat setelah dijalankan ulang.
  • Solusi: Glue job menulis ke staging table, lalu mengganti baris yang sudah ada di target sebelum data baru disimpan.
  • Merge: join staging table dengan target, lalu update dan insert. Upsert lewat Glue job menghilangkan duplikat.

Data sampling

  • S3 Select mengambil subset data dari object S3 dengan query mirip SQL. Catatan: S3 Select tidak tersedia untuk pelanggan baru sejak Juli 2024.
  • Athena dan Redshift: LIMIT clause.
  • EMR Spark: systematic, random, atau stratified sampling.
  • Data Wrangler: sampling untuk dataset seimbang. DataBrew: filter subset lewat transformasi.

Data skew

  • Data skew adalah distribusi tidak rata antar partition atau node, sehingga muncul bottleneck.
  • Deteksi: CloudWatch custom metrics (record per partition atau key, waktu proses) dengan alarm threshold.
  • Glue ETL: CloudWatch metrics dan Glue job bookmarks, yang membuat job lanjut dari record terakhir yang diproses.
  • EMR Spark: logging detail ke CloudWatch Logs, cari task lama, distribusi task tidak rata, partition yang skew. Real-time: Spark Streaming dengan Kinesis atau Kafka.
  • Penanganan: partitioning key dengan hash function, load balancing, replikasi data hotspot, shuffling, dynamic repartitioning.
  • Skew join: bloom filter atau skew join algorithm. EMR punya skew join optimization otomatis. Redshift punya adaptive join (hash join atau sort merge join).
  • Pre-processing (data binning, feature scaling, log transformation) dan task yang lebih kecil membantu meratakan beban.

Partitioning dan bucketing di Athena

  • Strategi umum: partisi per tanggal (year, month, day). Filter WHERE di kolom partisi hanya membaca prefix S3 terkait.
  • Partitioning dan bucketing sama-sama mengurangi data yang dipindai Athena.
  • Bucket di sini bukan S3 bucket. Bucket adalah file, hash function menentukan bucket tiap record, dan nomor bucket ada di nama file.
  • Engine v2 mendukung Hive bucketing. Engine v3 juga mendukung Spark bucketing. Default Hive. Untuk Spark, set bucketing_format ke spark di TBLPROPERTIES.

Redshift Spectrum dan DataBrew rules

  • Join data histori di S3 (terdaftar di Data Catalog) dengan tabel Redshift: Redshift Spectrum external table, lalu join dengan SQL.
  • DataBrew rules: completeness (null), format (email, nomor telepon), range (rentang angka), uniqueness (duplikat).
  • DataBrew menandai record yang tidak lolos, memberi statistik dan visualisasi, dan bisa diotomatiskan.

  • Tanpa CloudTrail data events, event object-level S3 tidak tercatat dan rule EventBridge berbasis CloudTrail tidak terpicu.
  • Saat latency tinggi, cek metric dulu sebelum menambah shard atau instance. Kalau CPU rendah dan tidak ada throughput exception, masalahnya di komponen lain.
  • Cek AWS Health Dashboard sebelum menyalahkan aplikasi sendiri.
  • Bucket di Athena bukan S3 bucket.
  • Kata "cost-effective" untuk job berkala di EMR mengarah ke transient cluster.
  • Di EMR dan Kinesis Data Streams, error handling harus diprogram sendiri.
  • Dashboard dengan search dan log analytics mengarah ke OpenSearch, bukan QuickSight.
  • Lebih banyak quality check tidak selalu lebih baik.

Lesson 1: Apply authentication mechanisms

Identitas di AWS

  • Authentication memastikan siapa kamu. Authorization menentukan apa yang boleh diakses setelah itu.
  • Metode: password-based, certificate-based, role-based. Kenali use case dan tingkat keamanannya.
  • Cara masuk: root user, IAM user, assume IAM role, atau federated identity.
  • IAM Identity Center: sign-in workforce, akses multi-account, dan SSO ke aplikasi SAML 2.0.
  • IAM user untuk satu orang atau aplikasi, kredensial permanen. IAM role bisa di-assume siapa saja yang butuh, kredensial sementara.
  • Tidak bisa sign in sebagai IAM group. Group hanya untuk memberi izin ke banyak user.
  • Service memanggil service lain lewat izin calling principal, service role, atau service-linked role.

Policy

  • Jenis: identity-based (ke user, group, role), resource-based (ke resource seperti S3 bucket atau KMS key), dan trust policy.
  • IAM role butuh dua policy: trust policy (siapa boleh assume) dan identity-based policy (boleh apa).
  • Tanpa allow eksplisit, default AWS adalah deny.
  • AWS managed policy dikelola AWS dan tidak bisa diubah. Customer managed policy dibuat sendiri, bisa dipasang ke banyak identitas.
  • Inline policy satu banding satu dengan identitas, ikut terhapus saat identitasnya dihapus.

Policy di endpoint dan service

  • Akses lewat S3 access point hanya jalan kalau access point policy dan bucket policy sama-sama mengizinkan. Atau bucket mendelegasikan kontrol ke access point.
  • User default tidak punya izin mengelola VPC endpoint. Condition key ec2:VpceServicePrivateDnsName membatasi endpoint berdasarkan private DNS name.
  • API Gateway punya dua model izin: API management (developer) dan API execution (caller). Set authorization type method ke AWS_IAM agar caller wajib kirim kredensial.
  • API Gateway ke Lambda: IAM role dengan trust policy untuk API Gateway plus izin lambda:InvokeFunction.
  • Interface VPC endpoint ke CloudFormation bisa diberi endpoint policy, misalnya menolak create stack lewat endpoint itu.

Jaringan, sertifikat, secrets

  • Pengaman jaringan: security group, network ACL, private subnet, bastion host, NAT gateway, route table, AWS VPN, Direct Connect, VPC Flow Logs, Security Hub, Network Firewall.
  • ACM membuat, menyimpan, dan memperpanjang sertifikat SSL/TLS X.509. Bisa impor sertifikat pihak ketiga, atau ekspor sertifikat AWS Private CA untuk PKI internal.
  • Siklus secret: create, store, use, destroy.
  • Secrets Manager terintegrasi IAM (termasuk resource-based policy di secret) dan KMS (AWS managed key atau customer managed key).
  • Rotasi otomatis terjadwal untuk RDS, Redshift, DocumentDB. Secret lain (API key, OAuth token) lewat Lambda kustom.

Lesson 2: Apply authorization mechanisms

Prinsip

  • Tujuannya least privilege untuk principal yang sudah terautentikasi.
  • Policy bisa dibangun dan dites sebagai kode di pipeline.
  • IAM Access Analyzer terus mencari resource yang bisa diakses dari luar akun. AWS Organizations menegakkan policy di banyak akun.

RBAC dan ABAC

  • RBAC: akses berdasarkan role. Lebih mudah dikelola.
  • ABAC: akses berdasarkan attribute dan tag di principal, resource, environment, atau application state.
  • Pilih ABAC kalau user butuh izin lintas role, role sulit didefinisikan, atau izin bergantung parameter dinamis.
  • Contoh: role bertag access-project heart, star, bolt. Satu policy memberi akses kalau tag role sama dengan tag resource.
  • ABAC granular tapi berat di awal. Keduanya bisa digabung (hybrid).

Amazon Redshift

  • User dikelola dengan CREATE USER dan ALTER USER, atau lewat JDBC/ODBC driver yang membuat temporary password.
  • Hanya superuser yang bisa membuat dan menghapus user. Superuser punya hak pemilik di semua database.
  • Dengan RBAC, grant dan revoke dilakukan di level role, tanpa mengubah izin tiap objek.

Lake Formation dan Parameter Store

  • Lake Formation mengatur akses data lake sampai level database, table, column, row, dan cell, untuk IAM dan external identity provider.
  • Berlaku saat diakses lewat Redshift Spectrum, Athena, Glue ETL, dan EMR for Spark.
  • LF-Tags dipasang ke database, table, atau column, mengganti ribuan definisi izin dengan beberapa tag.
  • Lake Formation bisa mengatur izin datashare Redshift secara terpusat.
  • Parameter Store (Systems Manager) menyimpan konfigurasi dan secret, tapi tanpa rotasi otomatis. Simpan secret di Secrets Manager lalu referensikan dari Parameter Store, nama diawali /.

Lesson 3: Ensure data encryption and masking

KMS, CloudHSM, TLS

  • AWS KMS membuat dan mengontrol key, terintegrasi dengan hampir semua service dan dengan CloudTrail untuk log pemakaian key.
  • CloudHSM dipakai kalau kamu harus mengelola langsung perangkat HSM. AWS mengurus hardware, patching, dan backup. Kamu mengurus scaling serta crypto account dan kredensial.
  • Di KMS dan CloudHSM, plaintext key tidak bisa dipakai di luar HSM.
  • Trafik antar data center dienkripsi di physical layer. Trafik di VPC dan antar VPC peering lintas Region dienkripsi di network layer. Semua endpoint AWS mendukung TLS.
  • Terminasi TLS dengan sertifikat sendiri: NLB, ALB, CloudFront, API Gateway.
  • Catatan: transkrip menulis "hardware security models", maksudnya hardware security modules.

Enkripsi at rest dan EMR

  • Pahami enkripsi at rest di EBS, S3, RDS, Redshift, ElastiCache, Lambda, EMR, Glue, SageMaker. SQS punya SSE untuk pesan sensitif.
  • Pahami beda client-side dan server-side encryption.
  • EBS terenkripsi di EMR tidak berarti local disk terenkripsi. Aktifkan local disk encryption di security configuration.
  • Enkripsi EBS terjadi di EC2 host. OS melihat data tidak terenkripsi kecuali ada end-to-end encryption.
  • Root volume semua node EMR terenkripsi: custom AMI. Salin snapshot ke target terenkripsi KMS, lalu pakai custom AMI ID di template CloudFormation.

Tokenization, masking, salt

  • Encryption memakai algoritma dan key, bisa didekripsi. Tokenization mengganti data dengan token acak tanpa proses matematis, relasinya disimpan di token vault.
  • Token tidak bisa dipetakan balik tanpa sistem tokenisasi. Contoh: pembayaran kartu kredit berulang.
  • Anonymization menghapus data sensitif. Masking menutupinya dengan nilai yang diubah.
  • Salt: data acak baru per password, digabung lalu di-hash, disimpan bersama hash. Salt tidak perlu dienkripsi.
  • Contoh tokenisasi serverless: Cognito, API Gateway, Lambda, KMS, DynamoDB client-side encryption library, cipher database dan application database. Lambda ke DynamoDB lewat gateway endpoint, ke KMS lewat interface endpoint.
  • Redshift Dynamic Data Masking (DDM) menyamarkan data saat query tanpa mengubah data tersimpan. Bisa per role, per cell dengan conditional column, dan beberapa policy di satu kolom.

Lesson 4: Prepare logs for audit

Retensi dan CloudTrail Lake

  • HIPAA dan PCI mewajibkan data disimpan dalam periode tertentu, bisa dicari, lalu dihapus sesuai aturan.
  • CloudWatch Logs default menyimpan log selamanya. Atur retention policy di log group.
  • CloudTrail Lake: query SQL terpusat atas event lintas akun dan Region, termasuk aktivitas dari luar AWS.
  • Event data store berisi satu kategori saja: CloudTrail events, Config configuration items, Audit Manager evidence, atau event luar AWS. Gabungkan dengan SQL JOIN.
  • Trail tidak mendukung otorisasi berbasis tag, event data store mendukung.

EMR dan analisis log

  • EMR menulis log di primary node, /mnt/var/log/, dan bisa mengarsipkan ke S3.
  • CloudTrail mencatat semua API call EMR. Trail mengirim terus ke S3. Tanpa trail, hanya event terbaru di Event history.
  • CloudWatch Logs Insights untuk mencari penyebab masalah. Field otomatis ditemukan untuk Route 53, Lambda, CloudTrail, VPC, dan log JSON.
  • Athena CloudWatch connector: log group jadi schema, log stream jadi table, view all_log_streams untuk semua stream.
  • Log group bisa di-stream ke OpenSearch Service nyaris real time lewat subscription.
  • Catatan: CloudWatch Events sekarang bagian dari Amazon EventBridge.

Lesson 5: Understand data privacy and governance

Proteksi sepanjang lifecycle

  • Field-level encryption mengenkripsi field sensitif saja dan menjaga struktur payload. Full payload encryption membuat payload tak terpakai sebelum didekripsi semua.
  • Lindungi data sedini mungkin saat ingestion. CloudFront plus Lambda@Edge melindungi data di edge sehingga sistem downstream tidak melihatnya.
  • Contoh pipeline: IoT Core (MQTT), Kinesis Data Firehose ke S3, Glue ETL memanggil Amazon Comprehend untuk mendeteksi data sensitif, Lake Formation membatasi akses analis di Athena.
  • Catatan: Kinesis Data Firehose sekarang bernama Amazon Data Firehose.

Sensitive data discovery

  • Scan terjadwal (default empat kali sehari, tiap 6 jam), sebelum crawler dan setelah redaksi atau tokenisasi.
  • Scan menambah minimal 5 sampai 10 menit, naik linear dengan ukuran objek, plus startup time konstan per job.
  • Komponen: bucket raw, scanning, manual review, scanned. Macie memindai, Step Functions mengorkestrasi Lambda, EventBridge memicu jadwal, SNS memberi notifikasi, API Gateway menerima keputusan reviewer.
  • Yang kurang: backup plan, DR plan, dan data privacy strategy agar backup atau replikasi tidak ke Region terlarang (data sovereignty).

Backup data lake

  • Storage admin memakai S3 versioning, Same-Region Replication, Cross-Region Replication, dan Object Lock.
  • AWS Backup membuat backup plan (frekuensi, retensi) di satu akun atau banyak akun lewat Organizations. Backup vault punya policy, key, dan lock sendiri.
  • Backup bucket raw biasanya cukup karena data turunan bisa dibuat ulang. Kalau raw berisi PII, backup data de-identified.
  • Pilih bucket lewat tag, misalnya "data protection level" = "critical".
  • Continuous backup untuk PITR, periodic untuk compliance. Copy to destination ke vault di akun atau Region lain. Enkripsi pakai KMS key milik vault.
  • AWS Backup Audit Manager melaporkan compliance backup lewat custom framework.

Redshift dan AWS Config

  • User Redshift tidak bisa di-drop kalau masih memiliki atau punya izin atas objek datashare.
  • Kolom rahasia di tabel Redshift: column-level GRANT dan REVOKE. Lake Formation plus Redshift Spectrum juga bisa.
  • AWS Config mencatat configuration item tiap resource lewat API describe atau list, termasuk related resource (contoh: ubah security group, instance terkait ikut dicatat).
  • Item dikirim lewat configuration stream ke S3. Tiap Config rule memakai Lambda function. Notifikasi bisa ke SNS.

Jebakan ujian

  • Authentication dan authorization sering ditukar.
  • IAM user kredensial permanen, IAM role kredensial sementara.
  • AWS managed policy tidak bisa diedit. Izin kustom yang dipakai ulang: customer managed policy, bukan inline.
  • Access point policy saja tidak cukup, bucket policy juga harus mengizinkan.

  • Parameter Store tidak punya rotasi otomatis, Secrets Manager punya.

  • Redshift DDM tidak mengubah data tersimpan.
  • Trail CloudTrail tidak mendukung otorisasi tag, event data store CloudTrail Lake mendukung.
  • Tanpa trail, CloudTrail tidak mengirim event ke S3, hanya Event history terbaru.
  • Backup vault terpisah dari S3 Object Lock dan bucket policy.
